# tisqlx

An async, pure-Rust SQL toolkit built **specifically for [TiDB]**, inspired by
[sqlx] but written from scratch. Runs on **tokio** with **rustls**, and supports
nothing else.

- **Compile-time checked queries** (`query!`, `query_as!`, `query_scalar!`, `query_file*!`) checked
  against a live TiDB, or against offline data generated by `tisqlx prepare`.
- **TiDB-native transactions**: pessimistic/optimistic mode per transaction, stale reads
  (`AS OF TIMESTAMP`, bounded staleness), causal consistency, and automatic retry of the whole
  transaction on write conflicts and deadlocks (`Pool::transaction`).
- **Migrations that match TiDB's semantics.** DDL is never transactional in TiDB, so every
  migration is recorded as *dirty* before it runs. A failure blocks later runs until it is
  repaired.
- A connection pool, nested transactions via savepoints, and a prepared-statement cache that
  survives DDL (also DDL run on another TiDB node).
- `#[tisqlx::test]`: async tests that each get a throwaway database, with migrations applied.
- Exposes TiDB primitives: `Tso`, `TiDbVersion` feature detection, `AUTO_RANDOM` ids through
  `last_insert_id()`, `tidb_read_staleness`, `tidb_isolation_read_engines` (TiFlash) and
  resource groups.

```rust
use tisqlx::{Isolation, Pool, RetryPolicy, StaleRead, TxnMode, TxnOptions};
use std::time::Duration;

let pool = Pool::connect("tidb://root@127.0.0.1:4000/app").await?;

// Checked at compile time: column types, nullability, bind count.
let user = tisqlx::query!("SELECT id, name, email FROM users WHERE id = ?", id)
    .fetch_one(&pool).await?;          // user.id: i64, user.name: String, user.email: Option<String>

// Optimistic transaction, retried on TiDB write conflicts (9007, 8002, 1213, ...).
pool.transaction_with(&TxnOptions::optimistic(), RetryPolicy::default(), |tx| Box::pin(async move {
    tisqlx::query!("UPDATE accounts SET balance = balance - ? WHERE id = ?", 10, from).execute(&mut **tx).await?;
    tisqlx::query!("UPDATE accounts SET balance = balance + ? WHERE id = ?", 10, to).execute(&mut **tx).await?;
    Ok::<_, tisqlx::Error>(())
})).await?;

// Isolation and mode together.
let tx = pool.begin_with(&TxnOptions::ReadWrite { mode: Some(TxnMode::Pessimistic), isolation: Some(Isolation::ReadCommitted) }).await?;

// With an error type tisqlx can't implement `Retryable` for (e.g. anyhow):
pool.transaction_retry_if(&TxnOptions::optimistic(), RetryPolicy::default(),
    |e: &anyhow::Error| tisqlx::error::is_retryable(e.as_ref()),
    |tx| Box::pin(async move { /* ... */ Ok::<_, anyhow::Error>(()) })).await?;

// Read-only stale read, served by the nearest replica.
let mut tx = pool.begin_with(&TxnOptions::stale_read(StaleRead::MaxStaleness(Duration::from_secs(5)))).await?;
```

## Crates

| crate | role |
|---|---|
| `tisqlx` | facade: re-exports and macros. Features: `macros`, `chrono`, `decimal` (all default) |
| `tisqlx-core` | driver: wire protocol, auth, TLS, types, pool, transactions, TiDB features, migrations |
| `tisqlx-macros(-core)` | `query!` family, `migrate!`, `#[derive(FromRow, Type)]` |
| `tisqlx-cli` | `tisqlx` binary: `database`, `migrate`, `prepare` |

## Connection URL

`tidb://user:pass@host:4000/db?ssl-mode=verify-identity&txn-mode=optimistic&resource-group=rg1`
(`mysql://` is accepted too). Query keys: `ssl-mode` (`disabled|preferred|required|verify-ca|verify-identity`),
`ssl-ca`, `statement-cache-capacity`, `timezone` (default `+00:00`), `txn-mode`,
`resource-group`, `require-tidb`, `socket`, `connect-timeout`. Any other key is set as a
session variable, e.g. `?tidb_isolation_read_engines=tikv,tiflash`.

The driver refuses to connect to a server that isn't TiDB unless `require-tidb=false`.

## Query macros

Set `DATABASE_URL`, either in the environment or in a `.env` file in the crate or one of its
ancestors. Nullability comes from TiDB's column metadata: TiDB keeps `NOT NULL` accurately,
and drops it for the nullable side of outer joins and for `MAX`/`MIN`/`SUM`/`AVG`. Override it
in the column alias:

| alias | meaning |
|---|---|
| `` AS `col!` `` | force non-null |
| `` AS `col?` `` | force `Option` |
| `` AS `col: MyType` `` | decode as `MyType` (any `Decode` type, e.g. a `#[derive(Type)]` enum) |
| `` AS `col: _` `` | infer from the struct field (`query_as!` only) |

Bind parameters are checked by count. TiDB reports every parameter as a string, so their types
are checked by the `Encode` trait bound, not against the server.

**Offline builds (CI):** run `tisqlx prepare` with a database available and commit
`.tisqlx/`. Then build with `TISQLX_OFFLINE=true`. `tisqlx prepare --check` fails when the
data is stale.

## Type mapping

| TiDB | Rust | feature |
|---|---|---|
| `BOOLEAN`/`TINYINT(1)`, `BIT(1)` | `bool` | |
| `TINYINT`..`BIGINT` (`UNSIGNED`) | `i8`..`i64` (`u8`..`u64`) | |
| `BIT(n)`, `YEAR` | `u64`, `u16` | |
| `FLOAT`, `DOUBLE` | `f32`, `f64` | |
| `DECIMAL` | `Decimal` (up to ~28 digits), `BigDecimal` (any precision, up to TiDB's 65), `i128`/`u128` (integral values) | `decimal`, `bigdecimal` |
| `CHAR`, `VARCHAR`, `TEXT` | `String`, `&str`, `Cow<str>`, `Box<str>`, `Arc<str>` | |
| `BINARY`, `VARBINARY`, `BLOB` | `Vec<u8>`, `&[u8]`, `[u8; N]`, `Box<[u8]>`, `Arc<[u8]>` | |
| `ENUM` | `String`, or a `#[derive(Type)]` enum | |
| `SET` | `types::Set` (list of members), `String` | |
| `JSON` | `serde_json::Value`, `Json<T>`, `&RawValue` | |
| `VECTOR` (TiDB 8.4+) | `types::Vector` (`Vec<f32>`) | |
| `DATE` | `chrono::NaiveDate`, `time::Date` | `chrono`, `time` |
| `DATETIME` | `chrono::NaiveDateTime`, `time::PrimitiveDateTime` | `chrono`, `time` |
| `TIMESTAMP` | `chrono::DateTime<Utc>`, `time::OffsetDateTime` (UTC session) | `chrono`, `time` |
| `TIME` | `chrono::TimeDelta`, `time::Duration`, `std::time::Duration` (≥ 0); `NaiveTime`/`time::Time` within a day | |
| `BINARY(16)`, `CHAR(36)` | `uuid::Uuid` (bytes or text), `uuid::fmt::Hyphenated` (text) | `uuid` |

Defaults: `macros`, `chrono`, `decimal`. The query macros infer chrono types when `chrono` is on,
else `time`. They infer `Decimal`, or `BigDecimal` for columns wider than 28 digits when
`bigdecimal` is on. `SET` columns become `types::Set`. UUIDs have no column type of their own, so
use an override such as `` AS `id: Uuid` ``. `DateTime<Utc>`/`OffsetDateTime` assume the session
time zone is UTC, which is the default `timezone` option.

## Authentication and TLS

`mysql_native_password` works on every transport. TiDB has no RSA key exchange, so a
`caching_sha2_password` account needs TLS or a Unix socket; tisqlx reports this clearly instead
of failing with "access denied". The default `ssl-mode=preferred` uses TLS whenever the server
offers it. Use `verify-identity` for TiDB Cloud.

## Tests with a database

```rust
#[tisqlx::test(migrations = "migrations")]
async fn creates_a_user(pool: tisqlx::Pool) {
    tisqlx::query!("INSERT INTO users (name) VALUES (?)", "a").execute(&pool).await.unwrap();
}
```

Each test gets its own database (`_tisqlx_test_<name>_<hash>`) on the server named by
`DATABASE_URL`. The database is recreated at the start of each run and dropped when the test
returns. If the test panics, it is left in place so you can inspect it.

## CLI

```sh
cargo install --path tisqlx-cli
tisqlx database setup                 # create DB + run migrations
tisqlx migrate add -r create_users    # reversible migration
tisqlx migrate run | revert [--all] | info
tisqlx migrate repair 20260101000000 --applied   # after fixing a dirty migration by hand
tisqlx migrate build-script           # build.rs so migrate!() picks up new files
tisqlx prepare [--check]              # offline data for query! macros
```

## Development

```sh
make db-up     # dedicated test TiDB v8.5.8 on port 4100 (never a shared server)
make test      # unit + mock-protocol + live tests
make ci        # lint, feature sets, tests, offline-data check
```

`cargo test` alone works without a database: live tests skip, and the macros compile from the
committed `.tisqlx/` data. See [TESTING.md](TESTING.md) for the test strategy. The live tests
create `tisqlx_t_*` databases and two unprivileged accounts, `tisqlx_sha` and `tisqlx_nat`, on
the test server. The `sqlx/` submodule is upstream sqlx, kept only as a reference.
